# Adapter: sagemaker

Amazon SageMaker AI real-time inference, in the customer's own AWS account. Adapter key `sagemaker`, source `backend/src/modules/model-deployments/adapters/sagemaker.adapter.ts`, fixture conformance `__tests__/conformance/sagemaker.conformance.spec.ts`.

SageMaker is the managed product; Amazon S3 is its native artifact source, because `ModelDataSource` accepts S3 and nothing else, and SageMaker pulls the objects itself through the execution role. almyty hands AWS a location, never bytes.

## Verified (docs.aws.amazon.com/sagemaker, fetched 2026-09-09)

- JSON 1.1 protocol: `POST https://api.sagemaker.{region}.amazonaws.com/` with `Content-Type: application/x-amz-json-1.1` and `X-Amz-Target: SageMaker.{Operation}`; SigV4 service name `sagemaker`. Inference at `https://runtime.sagemaker.{region}.amazonaws.com/endpoints/{name}/invocations`, with `X-Amzn-SageMaker-Inference-Component` naming the component to invoke.
- `CreateModel {ModelName, ExecutionRoleArn, PrimaryContainer, Containers[], Tags, VpcConfig}` returns `{ModelArn}`. A container definition is either an image plus artifacts, or a packaged model: `ModelPackageName` is "the name or ARN of the model package to use to create the model", which is how a SageMaker JumpStart or AWS Marketplace model is deployed without naming an image. https://docs.aws.amazon.com/sagemaker/latest/APIReference/API_CreateModel.html
- `S3ModelDataSource {S3Uri (required), S3DataType: S3Prefix | S3Object (required), CompressionType: None | Gzip (required), ETag, ManifestS3Uri, ManifestEtag, ModelAccessConfig, HubAccessConfig}`. An uncompressed `S3Prefix` (whose URI must end in a slash) lands under `/opt/ml/model`. `HubAccessConfig` carries a hub content ARN, which is how a JumpStart ModelReference is attached to an S3 source. There is no non-S3 member. https://docs.aws.amazon.com/sagemaker/latest/APIReference/API_S3ModelDataSource.html
- `CreateEndpointConfig {EndpointConfigName, ProductionVariants [{VariantName, ModelName?, InstanceType, InitialInstanceCount, InitialVariantWeight, VolumeSizeInGB, ManagedInstanceScaling {Status, MinInstanceCount >= 0, MaxInstanceCount >= 1}, RoutingConfig, ServerlessConfig}], KmsKeyId, Tags}` returns `{EndpointConfigArn}`. `CreateEndpoint {EndpointName, EndpointConfigName, Tags}` returns `{EndpointArn}`.
- `DescribeEndpoint {EndpointName}`: `EndpointStatus` in `OutOfService | Creating | Updating | SystemUpdating | RollingBack | InService | Deleting | Failed | UpdateRollbackFailed`, `FailureReason`, `ProductionVariants [{VariantName, InstanceType, CurrentInstanceCount, DesiredInstanceCount, CurrentWeight, DesiredWeight, VariantStatus}]`.
- Inference components: `CreateInferenceComponent {InferenceComponentName, EndpointName, VariantName, Specification {ModelName | Container {Image, ArtifactUrl, Environment}, ComputeResourceRequirements {NumberOfAcceleratorDevicesRequired, NumberOfCpuCoresRequired, MinMemoryRequiredInMb, MaxMemoryRequiredInMb}, StartupParameters {ModelDataDownloadTimeoutInSeconds, ContainerStartupHealthCheckTimeoutInSeconds}, BaseInferenceComponentName, InstanceType}, RuntimeConfig {CopyCount}, Tags}` returns `{InferenceComponentArn}`; the documented error is `ResourceLimitExceeded` 400. https://docs.aws.amazon.com/sagemaker/latest/APIReference/API_CreateInferenceComponent.html
- `DescribeInferenceComponent {InferenceComponentName}` returns `InferenceComponentStatus` in `InService | Creating | Updating | Failed | Deleting`, `FailureReason`, `RuntimeConfig {CurrentCopyCount, DesiredCopyCount, PlacementStatus[]}`, `Specification`, `EndpointName`, `VariantName`. https://docs.aws.amazon.com/sagemaker/latest/APIReference/API_DescribeInferenceComponent.html
- `UpdateInferenceComponentRuntimeConfig {InferenceComponentName, DesiredRuntimeConfig {CopyCount}}` returns `{InferenceComponentArn}`. https://docs.aws.amazon.com/sagemaker/latest/APIReference/API_UpdateInferenceComponentRuntimeConfig.html
- **Scale to zero needs inference components.** Verbatim from the prerequisites: an endpoint can scale in to and out from zero instances only if "It hosts one or more inference components. An endpoint can scale to and from zero instances only if it hosts inference components", and "In the endpoint configuration, for the production variant `ManagedInstanceScaling` object, you've set the `MinInstanceCount` parameter to `0`". Automatic scale-out from zero additionally needs the inference component registered as an Application Auto Scaling target on `sagemaker:inference-component:DesiredCopyCount` with `--min-capacity 0`, a target-tracking policy on `SageMakerInferenceComponentInvocationsPerCopy`, a step-scaling policy, and a CloudWatch alarm on `NoCapacityInvocationFailures`. Provisioning after a scale-out takes several minutes, and invocations during it error. https://docs.aws.amazon.com/sagemaker/latest/dg/endpoint-auto-scaling-zero-instances.html
- **Serverless inference is not an option for these models.** `ProductionVariantServerlessConfig` has only `MemorySizeInMB` (1024 to 6144), `MaxConcurrency` (1 to 200) and `ProvisionedConcurrency`; there is no instance type and no accelerator field anywhere on it, unlike `ProductionVariant.InstanceType` with its GPU list. It is a CPU, memory-sized tier and cannot host a GPU LLM. https://docs.aws.amazon.com/sagemaker/latest/APIReference/API_ProductionVariantServerlessConfig.html
- JumpStart is SageMaker's model hub, backed by a public hub named `SageMakerPublicHub`; `DescribeHubContent {HubName, HubContentName, HubContentType: Model | Notebook | ModelReference | DataSet | JsonDoc, HubContentVersion}` returns a `HubContentDocument` describing containers, scripts and instance recommendations.
- Errors: `ResourceLimitExceeded` 400 on the create and update calls; common errors `AccessDeniedException` 403, `UnrecognizedClientException` 403, `ExpiredTokenException` 403, `ThrottlingException` 400, `ValidationError` 400. The type is the body's `__type` (`com.amazon.coral.service#Name`). A missing endpoint or inference component is not a 404: it is a 400 `ValidationException` whose message says "Could not find".

## Deltas from the spec

- **Four resources per deployment**, named `almyty-{id}-model`, `almyty-{id}-cfg`, `almyty-{id}`, `almyty-{id}-ic`. A failure in a later create step deletes the earlier resources so nothing is left half-made.
- **The endpoint hosts an inference component, and the variant names no model.** This is the correction to the previous design, which set `ManagedInstanceScaling {MinInstanceCount: 0}` on a plain model-per-endpoint variant and claimed scale to zero from it. AWS does not support that: only an inference-component endpoint scales to zero. `scale(n)` is now `UpdateInferenceComponentRuntimeConfig` on the copy count, zero included, and managed instance scaling drains the instances behind it.
- **Automatic scale-out from zero is still the operator's to add.** The adapter creates no Application Auto Scaling target, policy or CloudWatch alarm, so an endpoint driven to zero copies comes back when almyty asks for copies again, not when a request arrives. Wiring the alarm is the follow-up.
- **Two model sources.** `s3://bucket/prefix` becomes `ModelDataSource.S3DataSource` with the `@pin` stripped and a trailing slash added, served by the LMI (DJL) vLLM deep learning container `763104351884.dkr.ecr.{region}.amazonaws.com/djl-inference:0.33.0-lmi15.0.0-cu128` with `HF_MODEL_ID=/opt/ml/model` and `OPTION_ROLLING_BATCH=vllm`; `environment` is merged over that and `image` replaces the whole URI (the DLC ECR account differs in a few regions and the LMI version moves). `sagemaker://model-package/<arn>` becomes `PrimaryContainer.ModelPackageName`, so a JumpStart or Marketplace model brings its own image and artifacts and almyty specifies neither. Anything else is refused with `ADAPTER_UNSUPPORTED_OPERATION` naming both accepted forms.
- **Weights are pulled by the execution role, not by registry keys.** The bucket must be readable by `executionRoleArn` and live in the customer's AWS account or be shared with it; a MinIO or cross-cloud registry cannot be served here without copying first, and the adapter says so rather than proxying the bytes.
- **State mapping**: the endpoint status first (`Creating` deploying; `Updating | SystemUpdating | RollingBack` scaling; `OutOfService | Deleting` stopped; `Failed | UpdateRollbackFailed` failed), then, once it is `InService`, the component status (`Creating` deploying, `Updating` scaling, `InService` ready, `Failed` failed, `Deleting` stopped). Zero copies or zero instances is `stopped`; an endpoint whose component has gone is `stopped` with a message; a missing endpoint is `missing`.
- **Cost is an estimate**: `hourlyRateCents` for the instance type times observed instances for the rate. The Pricing API needs `pricing:GetProducts` in us-east-1 and a product filter per instance type; not wired.
- Requests are signed with the in-repo SigV4 signer (`model-deployments/aws-request.ts`) because no SageMaker SDK client is installed.

## Not wired

- `DescribeHubContent` against `SageMakerPublicHub`, which would let a `jumpstart://{modelId}` version resolve its own image and artifact URI. The `HubContentDocument` is an opaque JSON blob whose schema the API reference does not publish, so the adapter takes the model package ARN instead of guessing at it.
- Serverless inference (`ServerlessConfig`), deliberately: it is CPU only.
