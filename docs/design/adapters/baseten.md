# Baseten adapter (`baseten`)

Verified 2026-09-08 against the hosted OpenAPI spec at `https://api.baseten.co/v1/spec` (OpenAPI 3.1) and docs.baseten.co. Source: `backend/src/modules/model-deployments/adapters/baseten.adapter.ts`.

## What was verified

- Base URL `https://api.baseten.co/v1`. Auth `Authorization: Bearer <api_key>`; the spec notes the legacy `Authorization: Api-Key <api_key>` scheme is still accepted. The adapter sends Bearer.
- Two ways to create a model exist. `POST /v1/models` takes a `source` of kind `library_listing` (fork a listing) or `model_archive` (a Truss archive uploaded with the STS credentials issued by `POST /v1/prepare_model_upload`, then referenced by `s3_key`). `POST /v1/llm_models` creates a BIS-LLM deployment "built from its config alone" (the spec says so under `prepare_model_upload`: no archive upload is required for BIS-LLM). Request `CreateLLMModelRequestV1`: `name` and `resources` required; `region`, `llm_version`, `llm_config` (free-form object), `environment_variables`, `model_metadata`, `autoscaling_settings` (`UpdateAutoscalingSettingsV1`), `additional_autoscaling_config`, `metadata`, `weights` (array of free-form weight configs "for BDN model weight distribution"). Response `LLMModelHandleV1`: `model_id`, `version_id` (the deployment id), `hostname`, `instance_type_name`.
- BIS-LLM config reference (docs.baseten.co/engines/bis-llm/bis-llm-config): top-level `resources.accelerator` (`H100`, `H100:2`, `A10G`, `L4`, `T4`, `A100`, `H200`, `B200`, ...), `use_gpu`; `weights[]` entries with `source` (`hf://...`, GCS, S3, Azure) and `mount_location`; `bis_llm.config` keys `engine_backend` (`vllm` | `trtllm`), `checkpoint_name`, `model_name`, `served_model_name`, `tensor_parallel_size`, `engine_config`. The training-job weight schema in the same spec (`CreateJobWeightConfigV1`) documents the source formats `hf://org/repo@rev`, `s3://bucket/prefix`, `gs://`, `r2://`, `cw://`.
- Model cache secrets (docs.baseten.co/development/model/model-cache): S3 sources read a workspace secret `aws_secret_json` whose value is JSON `{aws_access_key_id, aws_secret_access_key, aws_region}`; Hugging Face reads `hf_access_token`. Secrets are upserted with `POST /v1/secrets {name, value}` and are never readable back.
- Deployment read `GET /v1/models/{model_id}/deployments/{deployment_id}` returns `DeploymentV1` with `status` in `BUILDING | DEPLOYING | DEPLOY_FAILED | LOADING_MODEL | ACTIVE | UNHEALTHY | BUILD_FAILED | BUILD_STOPPED | DEACTIVATING | INACTIVE | FAILED | UPDATING | SCALED_TO_ZERO | WAKING_UP`, `active_replica_count`, `autoscaling_settings {min_replica, max_replica, autoscaling_window, scale_down_delay, concurrency_target, ...}`, `instance_type_name`, `region {slug, display_name}`.
- Scaling: `PATCH .../deployments/{id}/autoscaling_settings` with any of `min_replica`, `max_replica`, `autoscaling_window`, `scale_down_delay`, `concurrency_target`, `target_utilization_percentage`, `max_scale_down_rate`; response status `ACCEPTED | QUEUED | UNCHANGED`. `POST .../activate` and `.../deactivate` return `{success, no_op}`.
- Delete: `DELETE .../deployments/{id}` returns a tombstone `{id, deleted, model_id}`; `DELETE /v1/models/{model_id}` returns `{id, deleted}`.
- Cost: `GET /v1/billing/usage_summary?start_date&end_date` (range at most 31 days) returns `dedicated_usage.breakdown[]` with `billable_resource {id, kind, model_id, ...}`, `subtotal` and `compute_cost` in dollars, `minutes`. `GET /v1/instance_type_prices` returns `instance_types[] {instance_type {id, name, gpu_count, gpu_type, ...}, price}` with `price` in USD per minute.
- Regions: `GET /v1/regions` lists `{slug, display_name}`; regional environments are enabled per workspace by Baseten support, there is no public static list.
- Inference URLs (docs.baseten.co/inference/calling-your-model, reference/inference-api/overview): `https://model-{model_id}.api.baseten.co/environments/production/predict`, `.../deployment/{deployment_id}/{endpoint}`, OpenAI-compatible base `.../environments/production/sync/v1`.

## Deltas from the spec

- The spec's "generic vLLM truss with the registry URI in env" path is replaced by BIS-LLM: `POST /v1/llm_models` with `weights: [{source, mount_location: /models/almyty}]` and `llm_config.checkpoint_name = /models/almyty`. That avoids building and uploading a Truss archive from the API container. An S3 version passes `s3://bucket/prefix` (the registry's `@etag` pin stripped, Baseten's weight source format carries none for S3); an hf version passes `hf://org/repo@rev` unchanged.
- `llm_config` and `weights` are `additionalProperties: true` in the spec. The keys the adapter sends are the documented `bis_llm.config` and `weights[]` keys of config.yaml; that they are accepted verbatim by `/v1/llm_models` is verified at the schema level only and must be confirmed by the live conformance run.
- Registry read keys are a workspace-level secret (`aws_secret_json` by default, `registrySecretName` to change it) shared by every deployment in the workspace, because Baseten reads S3 credentials by secret name rather than per deployment. The adapter upserts it on each S3 deploy and never deletes it on teardown. A custom S3 endpoint goes in `environment_variables.AWS_ENDPOINT_URL`.
- Scale to zero is implemented as `deactivate` (immediate, `INACTIVE`, nothing billed) rather than `min_replica: 0`; a positive replica count patches `min_replica`/`max_replica` and calls `activate`.
- The deployment-scoped OpenAI-compatible base URL is composed as `https://{hostname}/deployment/{deployment_id}/sync/v1` from the two documented patterns (`/deployment/{id}/{endpoint}` and the `sync/v1` suffix of the production route); the production route is not used because a freshly created model's deployment may not be promoted yet.
- Cost: the burn rate comes from `instance_type_prices` matched on the deployment's `instance_type_name` (USD/minute times 6000 gives cents/hour), falling back to `hourlyRateCents`. Spend comes from the billing summary entries whose `billable_resource.id` is the deployment or whose `model_id` is the model, limited to the last 31 days; when the key lacks billing scope the estimate rate times uptime stands.
- `regions` in `capabilities()` is empty: placement is opt-in per workspace and listed dynamically.
