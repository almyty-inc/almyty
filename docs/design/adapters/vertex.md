# Adapter: vertex

Google Vertex AI, in the customer's own GCP project. Adapter key `vertex`, source `backend/src/modules/model-deployments/adapters/vertex.adapter.ts`, fixture conformance `__tests__/conformance/vertex.conformance.spec.ts`.

Vertex AI is the managed product, Model Garden is its catalog, and Cloud Storage is its native artifact source. The previous design streamed weights out of the almyty S3 registry into a vLLM container with `--load-format runai_streamer` and the registry's access keys as plaintext container environment. That was a workaround for a rule that no longer exists, and it is gone.

## Verified (fetched 2026-09-09)

The Vertex REST surface below was read from the live discovery document `https://aiplatform.googleapis.com/$discovery/rest?version=v1`, which is the authority for the v1 shapes, and cross-checked against the rendered reference pages.

### Model Garden one-call deployment

- `POST https://{location}-aiplatform.googleapis.com/v1/{destination}:deploy`, flat path `v1/projects/{projectsId}/locations/{locationsId}:deploy`, request `GoogleCloudAiplatformV1DeployRequest`, response `GoogleLongrunningOperation`. https://docs.cloud.google.com/vertex-ai/docs/reference/rest/v1/projects.locations/deploy
- Request body: `publisherModelName` ("The Model Garden model to deploy. Format: `publishers/{publisher}/models/{publisher_model}@{version_id}`, or `publishers/hf-{hugging-face-author}/models/{hugging-face-model-name}@001`") or `huggingFaceModelId` ("The Hugging Face model to deploy. Format: Hugging Face model ID like `google/gemma-2-2b-it`"), plus:
  - `modelConfig {acceptEula, huggingFaceCacheEnabled, modelDisplayName, huggingFaceAccessToken, modelUserId, containerSpec}`. The gated-model token field is `huggingFaceAccessToken`. `modelUserId` is "The ID to use for the uploaded Model, which will become the final component of the model resource name".
  - `endpointConfig {labels, dedicatedEndpointEnabled (deprecated in favour of dedicatedEndpointDisabled), dedicatedEndpointDisabled, privateServiceConnectConfig, endpointDisplayName, endpointUserId}`. `endpointUserId` is "Immutable. The ID to use for endpoint, which will become the final component of the endpoint resource name".
  - `deployConfig {fastTryoutEnabled, systemLabels, dedicatedResources}`, all optional: "The dedicated resources to use for the endpoint. If not set, the default resources will be used."
- The operation's metadata is `DeployOperationMetadata` and its response is `DeployResponse {publisherModel, model, endpoint}`.
- `GET v1/publishers/{publisher}/models/{model}` returns `PublisherModel` with `supportedActions.deploy` and `supportedActions.multiDeployVertex`, each entry carrying `containerSpec`, `dedicatedResources`, `artifactUri`, `publicArtifactUri` ("The signed URI for ephemeral Cloud Storage access to model artifact") and `deployMetadata {labels, sampleRequest}`. Model Garden's own artifacts live in Cloud Storage.

### Endpoints, models and the artifact source

- `POST {parent}/models:upload` (`v1/projects/{p}/locations/{l}/models:upload`) with `{model: {displayName, artifactUri, containerSpec {imageUri, command, args, env [{name, value}], ports [{containerPort}], predictRoute, healthRoute}, labels}}` returns an Operation whose response is `{model, modelVersionId}`.
- `Model.artifactUri` is "Immutable. The path to the directory containing the Model artifact and any of its supporting files." The custom container requirements page is explicit about what that path is and who reads it: "if you do provide model artifacts by specifying the `artifactUri` field, the container must load these artifacts when it starts running. When [Vertex] starts your container, it sets the `AIP_STORAGE_URI` environment variable to a Cloud Storage URI that begins with `gs://`. Your container's ENTRYPOINT instruction can download the directory specified by this URI in order to access the model artifacts. Note that the value of the `AIP_STORAGE_URI` environment variable isn't identical to the Cloud Storage URI that you specify in the `artifactUri` field ... Rather, `AIP_STORAGE_URI` points to a copy of your model artifacts." Cloud Storage is the only artifact store in the contract; there is no S3 anywhere in it. https://docs.cloud.google.com/vertex-ai/docs/predictions/custom-container-requirements
- `ModelContainerSpec.imageUri` is "Required. Immutable. URI of the Docker image to be used as the custom container for serving predictions. This URI must identify an image in Artifact Registry or Container Registry." A Docker Hub image is not accepted.
- Google's own prebuilt vLLM serving container is `us-docker.pkg.dev/vertex-ai/vertex-vision-model-garden-dockers/pytorch-vllm-serve:{tag}`, driven with `--model=`, `--tensor-parallel-size=`, `--gpu-memory-utilization=`, `--max-model-len=`, `--dtype=` args and `MODEL_ID`, `DEPLOY_SOURCE`, `HF_TOKEN` environment variables; it downloads from Hugging Face or from Cloud Storage. https://docs.cloud.google.com/vertex-ai/generative-ai/docs/open-models/vllm/use-vllm
- `POST {parent}/endpoints?endpointId=` returns an Operation whose response is the Endpoint. `GET {endpoint}` returns `deployedModels [{id, model, modelVersionId, displayName, dedicatedResources, status {availableReplicaCount, message, lastUpdateTime}, serviceAccount}]`, `trafficSplit`, `dedicatedEndpointDns`. `DELETE {endpoint}` returns an Operation.
- `POST {endpoint}:deployModel`, `POST {endpoint}:undeployModel {deployedModelId, trafficSplit?}` and `PATCH {endpoint}:mutateDeployedModel {deployedModel {id, dedicatedResources}, updateMask}` all return Operations; only the replica range, autoscaling metrics and logging flags are mutable.
- `DedicatedResources.minReplicaCount` is "Required. Immutable. The minimum number of machine replicas that will be always deployed on. This value must be greater than or equal to 1." Scale to zero exists only as a v1beta1 Preview (`scaleToZeroSpec`, `initialReplicaCount`), so on v1 the floor is one replica.
- `Endpoint.dedicatedEndpointDns` is "Output only. DNS of the dedicated endpoint ... Format: `https://{endpoint_id}.{region}-{uid}.prediction.vertexai.goog`", scheme included.
- OpenAI-compatible inference on a self-deployed endpoint: `POST v1/projects/{p}/locations/{l}/endpoints/{endpointsId}/chat/completions`, present in the v1 discovery document. The native surfaces `:predict` and `:rawPredict` remain.
- Errors use the google.rpc envelope `{error: {code, message, status}}`: 401 `UNAUTHENTICATED`, 403 `PERMISSION_DENIED`, 404 `NOT_FOUND`, 429 `RESOURCE_EXHAUSTED`, 400 `FAILED_PRECONDITION` (for example deleting an endpoint that still has a deployed model).
- Auth: OAuth2 bearer with the `https://www.googleapis.com/auth/cloud-platform` scope. Service-account keys are exchanged through the JWT bearer grant at `https://oauth2.googleapis.com/token`: RS256 JWT with `iss` (client_email), `scope`, `aud`, `iat`, `exp` (max 1 hour), posted as `grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer&assertion=...`.

### Usage and billing

There is no per-endpoint cost API. Cloud Monitoring publishes `aiplatform.googleapis.com/prediction/online/machine_count`, `.../replicas`, `.../prediction_count`, `.../error_count`, `.../prediction_latencies` and the accelerator and CPU utilisation series against the `aiplatform.googleapis.com/Endpoint` resource, labelled by `deployed_model_id`; actual dollars come from BigQuery billing export or the Cloud Billing Catalog API multiplied by observed replicas.

## Deltas from the spec

- **Two routes, chosen by the version's registry URI.** `vertex://publishers/{publisher}/models/{model}@{version}` and `hf://{owner}/{repo}` take the Model Garden route; `gs://bucket/prefix` takes the Cloud Storage route. Anything else, `s3://` included, is refused with `ADAPTER_UNSUPPORTED_OPERATION` whose message names all three accepted forms.
- **Model Garden route: one call, and Google's own choices.** `POST {parent}:deploy` with `endpointUserId` and `modelUserId` pinned to `almyty-{id}` and `almyty-{id}-model`, so the handle is complete before the operation finishes. `deployConfig` is sent only when the operator named a machine type; otherwise Model Garden uses the machine spec Google recommends for that model. No container is specified. A gated Hugging Face repository uses `modelConfig.huggingFaceAccessToken` from the credential, so the token goes to Google and never near the weights path. `readEndpoint` treats a 404 on an endpoint it has not yet seen, while the deploy operation is outstanding, as `deploying`; once the endpoint has been seen, a 404 is an orphan and reports `missing`.
- **Cloud Storage route: `artifactUri`, not a stream.** `models:upload` gets `artifactUri` set to the `gs://` prefix (the `@pin` stripped) and a container spec whose image defaults to Google's Model Garden vLLM container, with `--model=<gs uri>` in the args and `MODEL_ID` plus `DEPLOY_SOURCE` in the environment. No `ALMYTY_REGISTRY_URI`, no `AWS_ACCESS_KEY_ID`, no `AWS_ENDPOINT_URL`, no `runai_streamer`: those are deleted, and a conformance case asserts none of them appears on the wire. `predictRoute` and `healthRoute` default to `/v1/chat/completions` and `/health` (vLLM's OpenAI server) and are both overridable; Google's own notebook sample uses `/generate` and `/ping` for the non-OpenAI API server.
- **The default image moved off Docker Hub.** `vllm/vllm-openai:latest` cannot be used: Vertex requires Artifact Registry or Container Registry. The default is Google's `pytorch-vllm-serve` image, on a dated tag that moves, and `image` overrides it.
- **Vertex never scales dedicated resources to zero on v1** (`minReplicaCount >= 1`), so `scaleToZero` is `false`. `scale(0)` undeploys the model and keeps the endpoint (state `stopped`, zero burn); `scale(n)` mutates the replica range when deployed and redeploys when undeployed. A redeploy needs a machine type, so `readEndpoint` remembers the spec Model Garden chose; a redeploy with no spec on the handle is refused with `ADAPTER_CONFIG_INVALID` rather than guessing hardware.
- **Teardown undeploys first** because Vertex refuses to delete an endpoint with a deployed model, then deletes the endpoint and the model.
- **Replica count** is `deployedModel.status.availableReplicaCount` when Vertex reports it, otherwise the configured minimum.
- **URLs.** `openAiBase` is `{host}/{endpointName}` and `url` is that plus `/chat/completions`, where the host is the regional API base or, once Vertex reports one, the dedicated endpoint DNS with its scheme normalised (the field is documented as already carrying `https://`).
- **Cost is an estimate**: `hourlyRateCents` per replica times replicas. Cloud Monitoring plus the billing catalogue is the actuals path and is not wired.
- **Credentials**: `accessToken` is used as given; otherwise `serviceAccountJson` is exchanged and the token cached per client email until a minute before expiry. Both are `x-secret`. The exchange is done with Node crypto so the HTTP client stays injectable for fixtures.
