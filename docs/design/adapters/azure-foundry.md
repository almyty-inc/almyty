# Adapter: azure-foundry

Microsoft Foundry, in the customer's own Azure subscription, driven through the ARM REST API. Adapter key `azure-foundry`, source `backend/src/modules/model-deployments/adapters/azure-foundry.adapter.ts`, fixture conformance `__tests__/conformance/azure-foundry.conformance.spec.ts`.

Foundry Models serverless API deployment is the managed product, and the Foundry catalog is the native model source: for a listed model, Microsoft holds the weights and there is nothing to transfer. Where a source is needed, Azure reads its own registries and Azure Storage. The previous design pushed an `s3://` version through by putting `ALMYTY_REGISTRY_URI`, `MODEL_ID=/data/model` and the registry's access keys into a vLLM container's environment variables. That made almyty the delivery route for the weights, and it is gone.

## Verified (learn.microsoft.com, fetched 2026-09-09)

### Serverless API deployment: the catalog path

- Serverless API deployment is the current name for what was pay-as-you-go / Models as a Service, and it is the deployment option for Foundry Models generally: "All Foundry Models, including Foundry Models sold by Azure and select Models from partners and community, use serverless API deployments." No VM, container or cluster is provisioned by the customer. https://learn.microsoft.com/en-us/azure/foundry/concepts/deployments-overview
- `PUT https://management.azure.com/subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.CognitiveServices/accounts/{accountName}/deployments/{deploymentName}?api-version=2024-10-01` with body `{sku: {name, capacity}, properties: {model: {format, name, version}, raiPolicyName?, versionUpgradeOption?, scaleSettings?}, tags?}`; 200 or 201 returns the `Deployment` resource. `DeploymentProperties` also carries `capabilities`, `currentCapacity`, `callRateLimit`, `rateLimits`, `parentDeploymentName`, `dynamicThrottlingEnabled`. `DeploymentProvisioningState` is `Accepted | Creating | Deleting | Moving | Failed | Succeeded | Disabled | Canceled`. `DeploymentScaleSettings` is documented as deprecated in favour of `Deployment.sku`. https://learn.microsoft.com/en-us/rest/api/aiservices/accountmanagement/deployments/create-or-update?view=rest-aiservices-accountmanagement-2024-10-01
- `sku.name` accepts `GlobalStandard`, `GlobalProvisionedManaged`, `GlobalBatch`, `DataZoneStandard`, `DataZoneProvisionedManaged`, `DataZoneBatch`, `Standard`, `ProvisionedManaged`, `DeveloperTier`. For the Standard tiers `capacity` is a tokens-per-minute allocation in thousands, and billing is per token; the Provisioned tiers reserve and bill PTUs. https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/deployment-types
- Catalog listing: `GET .../providers/Microsoft.CognitiveServices/locations/{location}/models?api-version=2024-10-01` and `GET .../accounts/{accountName}/models?api-version=2024-10-01`, returning `{name, format, version, skus: [{name, capacity: {default}}]}`. https://learn.microsoft.com/en-us/rest/api/aiservices/accountmanagement/models/list?view=rest-aiservices-accountmanagement-2024-10-01
- OpenAI-compatible inference: `https://{resource}.openai.azure.com/openai/v1/` is the current recommended base, with implicit versioning and no `api-version` query parameter, and the deployment name goes in the request body's `model` field. It is also reachable at `https://{resource}.services.ai.azure.com/openai/v1/`. The vendor-neutral Azure AI Model Inference surface is `POST https://{resource}.services.ai.azure.com/models/chat/completions?api-version=...`. The base URL comes from the account resource, exposed as `properties.endpoint` on `Microsoft.CognitiveServices/accounts`. https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/endpoints
- The older hub-workspace equivalent is `Microsoft.MachineLearningServices/workspaces/{ws}/serverlessEndpoints/{name}` (`PUT` with `{location, sku, properties: {modelSettings: {modelId}, authMode, contentSafety}}`, `properties.inferenceEndpoint.uri`, keys via a `listKeys` action), documented under "Deploy models as serverless API deployments (classic)". It belongs to Foundry classic hub projects, not the current resource model. https://learn.microsoft.com/en-us/rest/api/azureml/serverless-endpoints/create-or-update?view=rest-azureml-2024-10-01

### Managed online endpoints: the container path

- `PUT .../Microsoft.MachineLearningServices/workspaces/{ws}/onlineEndpoints/{name}` with `location`, `identity`, `properties.authMode` (Key | AMLToken | AADToken), `properties.traffic`; the response carries `properties.scoringUri` and `provisioningState` in Creating | Deleting | Succeeded | Failed | Updating | Canceled. `POST .../listKeys` returns `primaryKey`/`secondaryKey`. `DELETE` removes the endpoint and its deployments.
- `PUT .../onlineEndpoints/{name}/deployments/{dep}` with `location`, `sku.{name,capacity}`, `properties.endpointComputeType: Managed`, `instanceType`, `environmentId`, `environmentVariables`, `model`, `modelMountPath`, `scaleSettings.scaleType`, `requestSettings`, liveness/readiness/startup probes. `provisioningState` in Creating | Deleting | Scaling | Updating | Succeeded | Failed | Canceled. `PATCH` accepts only `sku` and `tags`; `sku.capacity` is the instance count.
- `PUT .../environments/{name}/versions/{v}` with `properties.image`, `properties.osType`, `properties.inferenceConfig.{livenessRoute,readinessRoute,scoringRoute}.{path,port}`; BYOC deployments require `inferenceConfig`. `PUT .../models/{name}/versions/{v}` with `properties.modelType`, `properties.modelUri`; the model mounts under `<modelMountPath>/<name>/<version>`.
- These run virtual machines you pay for by the hour: "Managed online endpoints ... deploy models to powerful CPU and GPU machines in Azure ... The virtual machines are provisioned for you when you deploy models." They cannot scale to zero instances; the documented advice for an unused endpoint is to delete it.
- Model asset URIs are `azureml://`, `wasbs://`, `https://{account}.blob.core.windows.net/...` and `file://` for local registration. No page documents `s3://` or `gs://` as a model source; content in either has to be staged into Azure Storage or a datastore first. https://learn.microsoft.com/en-us/azure/machine-learning/how-to-manage-models?view=azureml-api-2
- Hugging Face models come from Azure's own system registry: the fully qualified asset id is `azureml://registries/HuggingFace/models/{model_name}/labels/latest` (the doc's worked example is `azureml://registries/HuggingFace/models/bert-base-uncased/labels/latest`), and the deployment names `model`, `instance_type` and `instance_count` and nothing else: no environment and no image. Azure downloads the weights from the Hub at deploy time. A gated model needs a workspace custom key connection named `HuggingFaceTokenConnection` holding `HF_TOKEN`, not an environment variable on the deployment. https://learn.microsoft.com/en-us/azure/machine-learning/how-to-deploy-models-from-huggingface?view=azureml-api-2

### Usage and billing

- `POST https://management.azure.com/{scope}/providers/Microsoft.CostManagement/query?api-version=2025-03-01`, where `{scope}` may be a single resource id, with `{type: "Usage", timeframe, dataset: {granularity, aggregation, grouping, filter}}`. Freshness: 8 to 24 hours on EA/MCA subscriptions, up to 72 hours on pay-as-you-go, with open-period estimates refreshed six times a day; the Query API returns unrounded costs. https://learn.microsoft.com/en-us/azure/cost-management-billing/costs/understand-cost-mgt-data
- Azure Monitor metrics on `Microsoft.CognitiveServices/accounts`, one-minute grain, splittable by `ModelDeploymentName`: `TokenTransaction` (prompt plus completion), `ProcessedPromptTokens`, `GeneratedTokens`, `AzureOpenAIRequests`, `AzureOpenAIProvisionedManagedUtilizationV2`, `ActiveTokens`. https://learn.microsoft.com/en-us/azure/foundry/openai/monitor-openai-reference

### Which product for which request

A model from the Foundry catalog is served by `Microsoft.CognitiveServices/accounts/{account}/deployments/{name}`: a deployment resource naming `format`, `name` and `version`, with nothing named container, instance or VM in its schema. A managed online endpoint is the fallback for weights Microsoft does not already hold, and it does run a container on hourly instances.

## Deltas from the spec

- **Three routes, chosen by the version's registry URI.** `foundry://{format}/{name}@{version}` takes the serverless API deployment; `hf://{owner}/{repo}` takes a managed online endpoint fed from the Azure HuggingFace registry; `azureml://` or a blob `https://` URL takes a managed online endpoint over a registered model asset. `s3://`, `gs://` and anything else are refused with `ADAPTER_UNSUPPORTED_OPERATION` whose message names all three accepted forms.
- **Catalog route.** One `PUT` on the Cognitive Services deployment, tagged with the almyty deployment and organization, after a `GET` on the account for `properties.endpoint`. `url` is `{endpoint}/openai/v1/chat/completions`, `openAiBase` is `{endpoint}/openai/v1`, and `details.modelId` is the deployment name, which is what goes in the OpenAI request's `model` field. `capacity` stays the operator's token-rate allocation: it is not derived from a replica count, because on this surface capacity is tokens per minute, not instances. `scale(0)` deletes the deployment (which frees the quota) and `readEndpoint` reports `stopped`; `scale(n)` puts it back at the configured capacity. Teardown deletes the deployment, not the account.
- **Hugging Face route: Azure's registry, not ours.** The deployment names `azureml://registries/HuggingFace/models/{repo}/labels/latest` and no environment, no image and no environment variables, so Azure's curated container serves it and Azure pulls the weights from the Hub. A gated model needs the workspace's `HuggingFaceTokenConnection`, which the adapter does not create; that is the follow-up. The catalog's model name for a namespaced repository is Azure's, so an operator who needs an exact asset id can pass the `azureml://registries/HuggingFace/...` URI directly and take the asset route instead.
- **Model asset route is the only one that names a container,** because Azure has no curated image for arbitrary weights. It registers the environment (vLLM, liveness and readiness on `/health` and scoring on `/v1/chat/completions`, port 8000) and a `custom_model` asset, mounts it at `/var/azureml-app/model`, and sets `SERVED_MODEL_NAME`, `MODEL_ID` (the mount path), and optionally `QUANTIZATION` and `MAX_MODEL_LEN`. No registry URI and no object-store keys are sent, and a conformance case asserts none appears on the wire.
- **Scoring URI proxies one route.** A managed endpoint forwards `scoringUri` to the environment's `scoringRoute` only. The adapter reports `scoringUri` as the endpoint URL; the gateway must call it as the chat completions endpoint and cannot list `/v1/models` through it (`details.chatCompletionsOnly`).
- **No scale to zero on managed online endpoints.** `scale(0)` deletes the deployment and leaves the endpoint and its URL in place; `scale(n)` recreates it from the spec kept on the ref. `readEndpoint` reports `stopped` while no deployment exists.
- **Traffic is routed after the deployment succeeds.** ARM rejects `traffic` naming a deployment that does not exist yet, so the first `readEndpoint` that sees the deployment `Succeeded` PUTs the endpoint with `traffic: { almyty: 100 }` and reports `deploying` once more.
- **Endpoint auth key.** The endpoint is created with `authMode: Key`; the key is fetched by the caller via `listKeys` and is never stored on the ref.
- **Cost.** A catalog deployment reports `spentCents: 0`, `ratePerHourCents: 0` and the operator's `inPerMTok`/`outPerMTok` as `perToken`, because it bills tokens; a managed online endpoint uses `hourlyRateCents` times `sku.capacity` over observed running time. The Cost Management Query API and the Azure Monitor token metrics above are the actuals path and are not wired.
- **Assets are not cleaned up.** Teardown deletes the endpoint or the serverless deployment; environment and model versions stay in the workspace as history.
- **Two api-versions.** `2024-10-01` for both `Microsoft.CognitiveServices` and `Microsoft.MachineLearningServices`, kept as separate constants because they move independently.
