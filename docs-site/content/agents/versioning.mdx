# Versioning and Rollback

Every change to an agent (and to your tools, APIs, and gateways) is tracked
automatically, so you can always see what changed and undo it. On the agent's
**Overview** tab, the **Change history** shows each version (who changed it and
when, expandable to the exact field diff). Below it, an **Audit log** records the
full activity trail. Nothing to turn on.

![Change History and Audit Log on an agent: every change tracked, expandable to a diff, with version saves](/screenshots/versioning-history.png)

## What's tracked

Created, configuration updated, tools changed, activated/deactivated, a version
saved, a rollback, an invocation: each with the timestamp, the user, and what
changed.

| Event | Description |
|-------|-------------|
| `created` | Agent was created |
| `updated` | Configuration, pipeline, or tools were modified |
| `activated` / `deactivated` | Status changed |
| `version_saved` | A version snapshot was created |
| `rolled_back` | Pipeline was restored from a previous version |
| `invoked` | Agent was executed |

## Version snapshots and rollback

A workflow agent keeps snapshots of its pipeline. Every time you save a change
to the pipeline, the previous one is kept as a snapshot with an auto-incremented
version number. They are listed on the agent's **Overview** tab under
**Pipeline versions**. To take a snapshot with a changelog of your own, call
`POST /agents/:id/versions` with `{ "changelog": "..." }`; the dashboard has no
button for it.

![Saving a version and the version list](/screenshots/versioning.png)

To restore one, find it in the list and click **Rollback**, then confirm. The
agent's pipeline is replaced with that snapshot, and the rollback itself is
recorded in the audit log. Rolling back never deletes newer versions, so you can
roll forward again at any time.

An autonomous agent has no pipeline snapshots; its changes are in the **Change
history** and the **Audit log** on the same tab.

## Good practice

- Before restructuring a pipeline, save a snapshot with a changelog, so there is always a named restore point.
- Write a real changelog: it is what makes the history useful later.
- Test the agent after a rollback to confirm the restored configuration behaves.
