# Hosted machines

A hosted machine is a computer almyty runs for you, so your agents can work on a project without you keeping a machine of your own switched on. You describe it once as an **environment**: which repository, what software it starts with, which websites it may reach. When an agent needs it, the machine starts. When nobody has used it for a while, it parks itself, and its files stay where they were for next time.

![The Hosted tab on the Runners page: environments with the state of your machine on each](/screenshots/runners-hosted.png)

Hosted machines are switched on per server. When they are not available, the **Hosted** tab says so, and you can still use [runners on your own machines](/runner).

## Create an environment

1. Open **Runners** in the sidebar and choose the **Hosted** tab.
2. Click **New environment**.
3. Fill in the page:
   - **Name**: lowercase letters, digits and dashes, such as `web-app`. Its tools are named after it.
   - **Repository** and **Branch** (optional): the https address of the project the machine works on.
   - **Starting point**: the software the machine starts with. Pick one from the list.
   - **Setup script** (optional): commands that get the machine ready, for example `npm ci`.
   - **Allowed sites**: the websites the machine may reach, one per line, such as `github.com` or `registry.npmjs.org`. Everything else is blocked. almyty itself and the repository are always allowed.
   - **Park after**: how many minutes without use before the machine stops. The page shows the range this server allows and the default.
   - **Who can use it**: **Only you**, **One team** or **Everyone**. Sharing with a team or everyone is part of the Business plan; without it, those choices are greyed out with a link to the plans.
4. Click **Create environment**. Nothing starts yet: your machine starts the first time an agent or tool uses the environment.

![Creating an environment on its own page](/screenshots/environment-new.png)

## Run an agent there

Open the agent, click **Edit**, and under **Capabilities** pick the environment in **Runs on**. Its runner work then happens on your machine in that environment. An agent runs either on a hosted environment or on your own machines, not both: picking an environment clears a chosen runner and its machine labels, and picking a runner clears the environment.

## Your machine and its files

Everyone who uses an environment gets a machine and files of their own. The environment's page shows yours:

| State | What it means |
|---|---|
| **running** | The machine is on and doing work, or waiting for the next call. |
| **waking** | It is starting because something needs it. An agent waits for it and then carries on. |
| **parked** | It stopped after its idle time. Its files are kept until the date shown, counted from the last time it was used. Using it again starts it and resets the date. |
| **failed** | It could not start. The reason is shown next to it. |

![An environment's page: your machine, the agents that run there, and its settings](/screenshots/environment-detail.png)

On the same page:

- **Suspend** parks a running machine now. Its files stay.
- **Release** lets the workspace go and deletes its files. You are asked once before it happens.
- **Agents that run here** lists the agents set to run on this environment.
- **Settings** is the same form as when you created it. Changes apply to machines that start after you save.
- **Delete** removes the environment, and every machine on it with its files.

Organization owners and admins see everyone's machines on an environment they can see, and can suspend or release them.

## For developers

- The pages call the `/environments` API: `GET /environments` (with `enabled`, whether hosted machines are on), `POST`, `GET`, `PATCH` and `DELETE /environments/:id`, `GET /environments/:id/workspaces`, and `POST /environments/:id/workspaces/:workspaceId/suspend` and `/release`.
- An agent's choice is `agentConfig.environmentId`. The server refuses it together with `runnerId` or `runnerLabels`.
- The Hosted tab is `/runners?tab=hosted`; an environment's page is `/runners/hosted/:id`.
- Hosted machines are off unless the server runs with `HOSTED_RUNNERS_ENABLED=true`. The idle time range, the images offered and how long parked files are kept are server settings; see `docs/hosted-runners.md` in the repository.
