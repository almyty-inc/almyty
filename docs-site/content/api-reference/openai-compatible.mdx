# OpenAI Compatible API

> This is the HTTP API reference. For UI walkthroughs, see [Getting Started](/) and the feature guides above.

![Agents list in the UI](/screenshots/agents-list.png)


An almyty agent can be called through an OpenAI-compatible chat completions
API, so an application built against the OpenAI SDK reaches an agent with a
base URL change and nothing else.

What that does and does not cover is set out below. An agent is not a model:
it runs its own pipeline and its own tools and hands back the finished answer.
Fields that would change that — client-declared tools, a forced response
format, more than one choice — are refused with a 400 naming the field rather
than accepted and ignored, because a caller whose tools never fire and who
gets no error has nothing to debug.

## Endpoints

```
POST https://api.almyty.com/v1/chat/completions
GET  https://api.almyty.com/v1/models
```

Authenticate with an almyty API key as a bearer token. `GET /v1/models` lists
the organization's active agents in the OpenAI model shape, each as
`agent:<id>`.

## Request

```bash
curl -X POST https://api.almyty.com/v1/chat/completions \
  -H "Authorization: Bearer $ALMYTY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agent:my-agent",
    "messages": [
      { "role": "system", "content": "You are a helpful assistant." },
      { "role": "user", "content": "What is the weather in Berlin?" }
    ],
    "temperature": 0.7,
    "max_tokens": 1024,
    "stream": false
  }'
```

### Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `model` | string | Yes | The agent, as `agent:<id>`, `agent:<name>`, or a bare id or name |
| `messages` | array | Yes | The conversation. This endpoint is stateless — send the whole history every turn |
| `temperature` | number | No | Applied to the run's LLM steps for this request only |
| `max_tokens` | number | No | Applied to the run's LLM steps for this request only |
| `stream` | boolean | No | Stream the answer as SSE |
| `stream_options` | object | No | `{ "include_usage": true }` adds a final usage-bearing chunk before `[DONE]` |

Limits: at most 100 messages, 100 KB per message, 1 MB per request body.

### Message roles

| Role | Description |
|------|-------------|
| `system` | Client instructions. Folded into the conversation the agent reads; it does not replace the agent's own system prompt |
| `user` | A user turn |
| `assistant` | A previous assistant turn — send these back for multi-turn conversations |
| `tool` | A tool result from an earlier turn, kept as its own turn |

The whole array reaches the agent. Because an agent prompt binds one string,
the conversation is rendered into it as a labelled transcript rather than
passed as a structured list; a single-turn request is passed through
unchanged.

### Fields that are refused

These come back as a `400` whose `error.param` names the field:

`tools`, `tool_choice`, `functions`, `function_call`, a `response_format`
other than `text`, `n` other than `1`, `top_p` other than `1`, a non-zero
`frequency_penalty` or `presence_penalty`, `stop`, `seed`, `logprobs`,
`top_logprobs`.

The defaults a client library sends without being asked to (`n: 1`,
`top_p: 1`, zero penalties) are accepted, since their behaviour is already
what happens.

```json
{
  "error": {
    "message": "This endpoint does not take client-declared tools. An almyty agent runs its own tools and returns the finished answer, so there is no turn at which one could be handed back to you. Give the agent the tools instead.",
    "type": "invalid_request_error",
    "code": "unsupported_parameter",
    "param": "tools"
  }
}
```

## Response

### Non-streaming

```json
{
  "id": "chatcmpl-uuid",
  "object": "chat.completion",
  "created": 1711234567,
  "model": "agent:my-agent",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "The current weather in Berlin is 12°C with partly cloudy skies."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 0,
    "completion_tokens": 0,
    "total_tokens": 43
  }
}
```

A run that does not complete comes back as a `502` carrying an error object,
not a `200`.

### Token usage

A run records one token total and nothing keeps the prompt and completion
halves apart, so `total_tokens` is measured and the other two are `0`. Every
response carries `x-almyty-usage-split: unavailable` to say so. Do not
attribute cost from the split.

### Streaming

With `stream: true` the response is Server-Sent Events:

```
data: {"id":"chatcmpl-uuid","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"role":"assistant"},"finish_reason":null}]}

data: {"id":"chatcmpl-uuid","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"content":"The "},"finish_reason":null}]}

data: {"id":"chatcmpl-uuid","object":"chat.completion.chunk","choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}

data: [DONE]
```

With `stream_options: {"include_usage": true}` one further chunk arrives
before `[DONE]`, carrying `usage` and an empty `choices` array.

A run that fails after the headers have gone out ends with a frame carrying
an `error` object, which is what both SDKs raise on:

```
data: {"id":"chatcmpl-uuid","object":"chat.completion.chunk","error":{"message":"...","type":"api_error","code":"agent_execution_failed","param":null}}

data: [DONE]
```

## Tools

An agent runs its own tools. A `tool_call` node executes inside the run and
the answer comes back finished, so there is no turn at which a tool could be
handed back for you to run, and no `tool_calls` in the response. Give the
agent the tools instead of declaring them on the request.

## Integration examples

### Python (openai library)

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://api.almyty.com/v1",
    api_key="your-almyty-api-key",
)

response = client.chat.completions.create(
    model="agent:my-agent",
    messages=[
        {"role": "user", "content": "My name is Frane."},
        {"role": "assistant", "content": "Noted."},
        {"role": "user", "content": "What is my name?"},
    ],
)

print(response.choices[0].message.content)
```

### JavaScript (openai library)

```javascript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://api.almyty.com/v1",
  apiKey: "your-almyty-api-key",
});

const response = await client.chat.completions.create({
  model: "agent:my-agent",
  messages: [{ role: "user", content: "Summarize today's news" }],
});

console.log(response.choices[0].message.content);
```

## Limitations

- An agent's pipeline decides which model runs each step; `temperature` and
  `max_tokens` are the only sampling controls a request can set
- The prompt/completion token split is not measured — see above
- Client-declared tools and structured-output modes are refused, not ignored
