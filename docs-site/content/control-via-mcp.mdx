# Control almyty via MCP

You can set up and run almyty by asking your AI assistant, instead of clicking through the dashboard. Connect an assistant such as Claude Code, Cursor or Claude Desktop to almyty, then ask in plain words: "import our orders API and publish the refund tools", or "put the support agent on Slack with a $2 limit per run". The assistant does the same things you would do in the dashboard.

This works through **MCP** (Model Context Protocol), the common way AI apps connect to outside tools. almyty is itself an MCP server.

This is different from [publishing your own tools on an MCP gateway](/gateways/mcp). There, an AI uses *your* company's tools. Here, it uses *almyty's own* tools to set almyty up.

## Connect your assistant

Add almyty to your assistant as an MCP server with the address `https://api.almyty.com/mcp`, and sign in once. The exact commands are under [For developers](#for-developers).

## What your assistant can do

It has 69 tools covering almost everything in the dashboard. None of them depends on your plan.

| Area | What it can do |
| --- | --- |
| **APIs** | Connect, update and delete APIs; import an API description and check on the import |
| **Tools** | List the tools made from your APIs, switch one on, delete one |
| **Tool hub** | Search ready-made templates and install one as an API with its tools |
| **Gateways** | Create and delete gateways, add tools to them, add or remove sign-in |
| **Agents** | Create, change, switch on and off, delete and run agents |
| **Channels** | Put an agent where people are: add, check, publish and unpublish channels, set branding and visitor rules, build downloadable apps |
| **Providers** | Connect model vendors and list them |
| **Models** | List models, refresh the list, check a model, preview which model an agent would use, list models on your own cloud accounts |
| **Credentials** | List the services you can connect, add a credential, see and change who may use it |
| **Memory** | Read, write, search and tidy up what agents remember |
| **Runners** | List your runners |
| **Organization** | List members and their roles, for example to pick who may use a credential or who approves |
| **Cost** | List spending budgets and see what has been spent this period |
| **Analytics** | Get one report at a time: overview, tools, gateways, models, agent runs, alerts, routing failures |
| **Approvals** | See what is waiting for approval and approve or reject it, so a paused run carries on |

## Examples

Ask your assistant:

```text
> Import the Stripe OpenAPI spec, then publish an MCP gateway with just the refund tools.
```

It imports the description, waits for the import, finds the refund tools, creates a gateway with them, adds a key, and hands you back a ready address, without you opening the dashboard.

Or put an agent in front of people from start to finish:

```text
> Put my support-bot agent on Slack as Acme Support, with a $2 limit per
> run, and publish it.
```

It sets the name and the limits a public channel needs, adds the Slack channel, checks it, and publishes it.

## What it cannot do

A few things are left out on purpose:

- **Change an existing gateway.** Gateways can be created and wired up, but editing one that is already published is done in the dashboard or the [REST API](/api-reference/authentication), so a stray request cannot quietly rewrite a live address.
- **Write tools by hand.** Tools come from importing an API description or installing a template.
- **Switch an agent on directly.** A new agent always starts as a draft. Switching it on runs its checks first, and only a switched-on agent can be run.

## For developers

Add the built-in `almyty` system gateway at the universal `/mcp` endpoint:

```bash
claude mcp add almyty --transport http https://api.almyty.com/mcp
```

Or in a client config file:

```json
{
  "mcpServers": {
    "almyty": { "url": "https://api.almyty.com/mcp" }
  }
}
```

Authenticate once with `npx @almyty/auth login`; the server announces itself as `almyty`.

The management server speaks the same MCP versions as every gateway: **2026-07-28**, **2025-11-25** and **2025-06-18**, plus 2025-03-26 and 2024-11-05 for older clients (see [MCP gateway, Protocol versions](/gateways/mcp#protocol-versions)). Its tools carry titles and annotations (`list_*` and `get_*` only read, `delete_*` destructive), and a tool that returns a record also returns it as `structuredContent`. An unknown tool name is a `-32602` error. Its tool set does not change, so it reports `tools.listChanged: false` and a `subscriptions/listen` stream on it only keeps alive.

The tools, by area:

| Area | Tools |
| --- | --- |
| APIs | `create_api`, `list_apis`, `update_api`, `delete_api`, `import_schema`, `check_import_status` |
| Tools | `list_tools`, `activate_tool`, `delete_tool` |
| Tool hub | `list_tool_templates`, `install_tool_template` |
| Gateways | `create_gateway`, `list_gateways`, `delete_gateway`, `assign_tools_to_gateway`, `add_auth_to_gateway`, `remove_auth_from_gateway` |
| Agents | `create_agent`, `list_agents`, `update_agent`, `activate_agent`, `deactivate_agent`, `delete_agent`, `invoke_agent` |
| Channels | `list_channels`, `add_channel`, `get_channel`, `check_channel`, `update_channel`, `delete_channel`, `publish_channel`, `unpublish_channel`, `get_public_settings`, `update_public_settings`, `build_channel`, `list_builds` |
| Providers | `add_provider`, `list_providers` |
| Models | `list_models`, `sync_models`, `validate_model`, `preview_model_routing`, `list_model_deployments`, `list_model_versions` |
| Credentials | `list_connectors`, `list_connections`, `start_connection`, `complete_connection`, `list_connection_grants`, `grant_connection`, `list_credentials` |
| Memory | `memory_put`, `memory_get`, `memory_list`, `memory_search`, `memory_delete`, `memory_supersede`, `memory_consolidate`, `memory_sync`, `memory_transfer`, `memory_list_backends`, `memory_backends_health` |
| Runners | `list_runners` |
| Organization | `list_org_members` |
| Cost governance | `list_budgets`, `get_spend` |
| Analytics | `get_analytics` |
| Approvals | `list_approvals`, `decide_approval` |

The first example chains `import_schema`, `check_import_status`, `list_tools`, `create_gateway`, `assign_tools_to_gateway` and `add_auth_to_gateway`. The second chains `update_public_settings`, `add_channel`, `check_channel` and `publish_channel`.

What is left out: there is no `update_gateway` and no `create_tool` (`activate_tool` and `delete_tool` manage what an import produced). Status is not a settable field: `create_agent` always produces a draft, `activate_agent` is the only path to active because it runs pipeline validation first, and `invoke_agent` refuses an agent that is not active.
