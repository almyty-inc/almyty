# Hosted chat app

Publish an agent as a branded, full-page chat at `https://<app-slug>.almyty.app`. There is no widget to embed and no separate frontend to deploy.

![A branded hosted chat app on its own address](/screenshots/apps-hosted-chat.png)

The page carries your app's name, colour, greeting, and AI disclosure. Visitors get streaming replies and conversation history without seeing the almyty dashboard.

## Publish from Apps

1. Open **Apps** and create an app, or select one you already have.
2. On **Agents**, attach at least one autonomous agent and choose the default agent that answers.
3. On **Settings**, set the name and colour visitors see, the greeting, the access mode, and the spending limits.
4. On **Distributions**, select **Add distribution**, then choose **Web app**.
5. Open the Web app card. Resolve any listed blockers, then select **Publish**.

The distribution changes to **Live** when the hosted chat is answering. Open `https://<app-slug>.almyty.app` to test it as a visitor.

![The Web app distribution after publication](/screenshots/apps-web-published.png)

The address comes from the app slug. It must be 3 to 63 characters, using lowercase letters, numbers, and hyphens without a hyphen at either end. Reserved service names cannot be used.

## What a visitor gets

A visitor can start a chat, receive a streaming reply, and reopen earlier conversations. Public-link visitors do not need an almyty account. An anonymous visitor still has a separate record, keyed by a cookie scoped to that app's host, so one visitor cannot read another visitor's conversations.

Unpublishing turns the chat off without deleting its address or settings. Publishing it again restores the same distribution.

## Protect model spend

An app that uses **Anyone with the link** cannot be published until all three limits are set on **Settings**:

- a cost ceiling per run;
- a request limit per visitor, per hour; and
- a request limit per IP address, per hour.

These are enforced publication rules. The distribution dialog names each missing setting before the app can go live, so a public URL cannot spend against your model keys without a ceiling.

The app-level access selector also includes email verification, OAuth, and SSO. Gated modes do not require public-link limits because the identity gate stands between an unknown visitor and your model spend. SSO requires a commercial entitlement.

## AI disclosure

Every hosted chat shows an AI disclosure under the composer by default. You can change the wording on **Settings**. Removing it requires the white-label entitlement, and the removal is recorded.

See [Compliance](/compliance) for the full EU AI Act mapping.

## Addresses in each environment

Hosted apps and the dashboard use separate domains:

| Environment | Dashboard | Hosted app |
|---|---|---|
| Production | `app.almyty.com` | `<app-slug>.almyty.app` |
| Staging | `app.staging.almyty.com` | `<app-slug>.staging.almyty.app` |
| Development | your development dashboard | `<app-slug>.dev.almyty.app` |

Keeping the app on its own host lets the visitor cookie stay scoped to that app instead of the dashboard or API.

## Self-hosting

Hosted chat is part of the Apache-licensed core. To serve apps on a domain you control:

1. Point a wildcard DNS record at your deployment, for example `*.chat.acme.com`.
2. Set `HOSTED_CHAT_BASE_DOMAIN=chat.acme.com` on both the API and frontend containers. The frontend reads it at runtime, so the same image can be used in every environment.
3. Route `/api` on every tenant host to the API and strip the `/api` prefix. Route every other path to the frontend. Keeping these calls same-origin is what keeps the anonymous visitor cookie on the tenant host.
4. Issue a wildcard certificate for the domain and attach it to the tenant-host ingress.

An app with the slug `support` is then available at `https://support.chat.acme.com`.

### Wildcard certificates need DNS-01

Let's Encrypt does not issue wildcard certificates through an HTTP-01 challenge. Use DNS-01, which means your certificate controller needs permission to create TXT records in the zone. If your issuer has no solver for that DNS provider, move the zone or delegate `_acme-challenge` to one it can update.

A certificate per tenant also works, but Let's Encrypt limits issuance to 50 certificates per registered domain each week.

## What is commercial

Two options require a commercial entitlement:

- removing the almyty mark with white-label mode; and
- using SSO as the app access mode.

Public links, email verification, and OAuth remain in the core edition.
