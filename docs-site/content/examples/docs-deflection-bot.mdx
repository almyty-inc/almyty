# Answer common questions from your docs

Your documentation already has the answer, but people ask in Slack anyway. This assistant answers product and setup questions from your own documentation, right where they were asked, and says which page it used. When the docs don't cover a question, it says so and opens a ticket, so your team only sees the questions that really need a person.

For a full walk-through with screenshots, see [Website product chat](/examples/website-product-chat) (for customers) or [Internal help desk](/examples/internal-help-desk) (for staff).

## What you need

- Your documentation, reachable in one of two ways: your help center's search connected as an API, or the pages themselves added to almyty's memory.
- Optionally, your ticket system's API, so unanswered questions become tickets.
- A Slack or Discord workspace where you can add an app.

## How to build it

1. **Give it your docs.** Either open **APIs**, click **Connect an API** and connect your help center's search, or, for a smaller set of pages, open **Memory**, click **Add memory**, paste a page, and under **Advanced** set **Kind** to **Document**.
2. **Create the assistant.** Open **Agents**, click **Create agent** and switch to **Autonomous**. In **Instructions**, write: "Answer only from the docs, and always name the page you used. If the docs don't cover it, say so and open a ticket."
3. **Add the tools.** Under **Tools and APIs**, pick the docs search and your ticket system's "create ticket" tool. If you used memory, turn on **Remember between conversations** and set **Whose memory** to **Shared by all agents**, so it reads what you added. Save.
4. **Add a rule it can't argue with.** On its **Constraints** tab, add "Never invent a feature or a limit that isn't in the docs."
5. **Put it in Slack or Discord.** On its **Channels** tab, click **Add channel**, pick **Slack** or **Discord**, add the app's keys and publish. People mention it and it answers in the thread.

## Ideas

- Point it at internal runbooks instead of public docs, for an operations help desk.
- Turn on verification (**Configure verification** on its **Overview** tab), so a second model checks that the cited page really supports the answer.
- Look at which questions ended in a ticket: they tell you which docs to write next.
