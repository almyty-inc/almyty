# Give an old SOAP service a modern front door

For companies with a core system that still speaks SOAP (an older way for systems to talk to each other) and no appetite to rewrite it. almyty reads the service's description file (its WSDL), turns each operation into a clean tool, and handles the old message format for you. Modern AI tools and assistants can then use the old system without anyone touching it.

For example: a twenty-year-old stock system becomes "check stock level" and "reserve items" tools your assistants can call.

## What you need

- The service's WSDL (a link or a file) and its sign-in details, if it has any.

## How to build it

1. **Connect the service.** Open **APIs**, click **Connect an API**, pick **SOAP / WSDL**, give the WSDL link or file, and click **Connect API**. almyty reads the address from it and builds each operation's inputs from the service's own types. Add the sign-in details when asked.
2. **Check the tools.** Each operation is now a tool with named inputs and outputs. Nobody using it sees the SOAP messages.

   ![An imported service, every operation turned into a tool](/screenshots/quickstart-api-imported.png)

3. **Keep the password in one place.** The service's user name and password go in [Credentials](/credentials), so there is one place to change them.
4. **Open it up.** Give the tools to your own assistants under **Tools and APIs**, or create an **MCP** gateway under **Gateways**, **Create gateway**, so AI tools such as Claude Code can call the service, with keys, limits and a record of every call.

## Ideas

- OpenAPI, GraphQL and gRPC services connect the same way, so old and new systems end up in one place.
- Put several old services behind one gateway.
