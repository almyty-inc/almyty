# SDK tools

Connect an npm package as an SDK API, then turn one of its mapped methods into
a tool. The API owns the package and version; the tool chooses the export,
constructor arguments, method and inputs.

## Create one in the UI

1. Open **APIs → Connect API** (`/apis/new`) and choose **SDK / npm library**.
2. Add the package names and versions. If needed, expand the private-registry settings and provide the registry URL, scope and credential.
3. Create the API and wait for package analysis to finish. Its SDK maps describe the available exports, methods and parameter types.
4. Open **Tools → Create tool** (`/tools/new`) and select **SDK / npm package**.
5. Name the tool, choose its **SDK API**, then select a package, class or export, and method from the discovered map.
6. Map each constructor or method argument to a tool **parameter**, a fixed **literal**, or a **credential** path. Parameter mappings build the tool's input schema.
7. Optionally choose a response data path and inspect the generated-code preview.
8. Set visibility and click **Create tool**. Test the saved tool from its detail page before assigning it to an agent or gateway.

Package analysis happens on the API, not through a separate Discover button on
the tool-creation page. If the SDK API or method is missing, check the API's
analysis result before continuing.

## What is stored and executed

The tool stores an `sdkConfig`: package name and version, imports, optional
client construction, method call and argument mappings. At execution time,
almyty assembles JavaScript from that configuration and runs it through the
SDK execution path. You do not need to paste generated code into the tool.

The schema comes from the SDK map and the arguments you expose as parameters.
Review it before publishing: package type information and runtime behavior can
differ, and a mapped method still needs a real test with representative inputs.

## Credentials

Create secrets in the [credential vault](/credentials), then use credential
mappings for constructor or method arguments that need them. A mapping stores
a reference such as `credentialName.field`, not the secret itself. Use literals
for non-secret constants and parameters for values callers should supply.

Private registry credentials are configured on the SDK API. They authorize
package retrieval and are separate from the credentials a method needs when
it calls an upstream service.

## Packages and runtime limits

Package installation and introspection must succeed before methods are
available to select. Native addons, host access and outbound requests remain
subject to the runtime's security restrictions; installation alone does not
prove every export can run.

Use the [API reference](/api-reference) for SDK API creation, package maps and
tool configuration, and [JavaScript tools](/tools/javascript-tools) for the
code-execution model.
