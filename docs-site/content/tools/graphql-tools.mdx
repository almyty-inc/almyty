# GraphQL tools

GraphQL is a way many modern systems let you ask for exactly the data you want in one request. Connect a system's GraphQL API and every query (a question, such as "find a customer by email") and every mutation (a change, such as "close a deal") becomes a tool your assistants can use.

## Connect a GraphQL API

1. Open **APIs** and click **Connect an API**.
2. Pick **GraphQL**.
3. Give almyty the API's description: a link, a file or the text. The GraphQL address itself works too, because most GraphQL APIs describe themselves when asked.
4. Click **Connect API**. almyty imports it in the background, and the next page asks only for what is missing, usually the key, which you pick from [Credentials](/credentials) or create right there.
5. Open **Tools**: each query and mutation is now a tool, as a draft. Test the ones you want on their **Test tool** tab, then activate them.

The API keeps its key, and every tool made from it signs in with it. A call that comes back with GraphQL errors is reported to the assistant as a failed call, with the API's own error messages.

## For developers

### Results and errors

Tools made from a connected GraphQL API return the response's `data`. A response whose `errors` list is not empty is a failed result, with the messages joined into the error (`GraphQL errors: ...`).

### A tool with its own query

A tool can also carry a single query of its own in `graphqlConfig`, created through the [Tools API](/api-reference/tools-api):

```json
{
  "name": "search_repositories",
  "description": "Search repositories by keyword",
  "type": "query",
  "executionMethod": "graphql",
  "apiId": "<connected API id>",
  "parameters": {
    "type": "object",
    "properties": {
      "query": { "type": "string", "description": "Search query" },
      "first": { "type": "integer", "description": "Number of results", "default": 10 }
    },
    "required": ["query"]
  },
  "graphqlConfig": {
    "query": "query SearchRepos($query: String!, $first: Int!) { search(query: $query, type: REPOSITORY, first: $first) { repositoryCount } }"
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `graphqlConfig.endpoint` | string | GraphQL URL; overrides the linked API's base URL |
| `graphqlConfig.query` | string | The query or mutation |
| `graphqlConfig.variables` | object | Optional map of variable name to a `{name}` template; without it, all inputs are sent as variables unchanged |
| `graphqlConfig.headers` | object | Extra request headers |
| `graphqlConfig.responseMapping.dataPath` | string | Dot path to return instead of the whole response |
| `configuration.timeout` | number | Timeout in milliseconds, default `30000` |

With a linked API (`apiId`), the call signs in with that API's key. Such a tool returns the endpoint's whole JSON response (or the part at `responseMapping.dataPath`); only a failed HTTP request is a failed result. A `{name}` template inserts the input as text, so leave `variables` out when numbers and booleans must keep their types.

### Tips

- Pass values as variables; don't build them into the query text.
- Name your operations, which helps when reading the API's logs.
- Ask only for the fields you need, so the assistant reads less.
