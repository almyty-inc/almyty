# Get started

almyty turns any API into tools your AI agents can call, served over MCP, A2A, UTCP, and Agent Skills. This page takes you from an empty account to your own API running inside Claude Code (or Cursor, or any MCP client) in a few minutes.

Do every step in the UI or from the CLI. Start on the [hosted platform](https://app.almyty.com) (no card required), or [self-host](/self-hosting) with one container.

In the app, open **Guide** in the sidebar footer (`/guide`). It groups the setup into four jobs: give an AI your API, build an agent, publish an app, or connect your own machine. Progress comes from the resources and successful calls in your organization, so work done through the CLI counts too. You can hide the dashboard guide card or page introductions without losing access to the guide.

```bash
npm install -g @almyty/cli
almyty login
```

## 1. Turn an API into tools

Open **APIs → Connect an API** (`/apis/new`). Paste a link to the API's description, drop the file, or paste its content, then click **Import**. almyty works out the format (OpenAPI 3, Swagger 2, GraphQL, WSDL or .proto) and reads the name, address and sign-in scheme from it. For GraphQL you can also paste the endpoint's own URL. The import runs in the background, and the next page asks only for what is missing: usually your key, and the address when the description has none. **Advanced** lets you set the name, address, sign-in type and who can use it yourself.

To replace the description later, open the API and click **Update the description**. For an npm package, pick **Import an npm package** under **Other ways**. For a single HTTP call, create a [tool](/tools/http-tools) instead.

Every operation in the schema becomes a typed, validated tool. No code.

![Tools generated from the schema](/screenshots/quickstart-api-imported.png)

## 2. Publish a gateway

Tools reach your AI through a gateway. Open **Gateways → Create gateway** (`/gateways/new`), choose a tool gateway and **MCP**, and assign the tools you just made from the **Tool scoping** tab.

![A gateway with tools assigned](/screenshots/gateway-detail-tools.png)

Each gateway serves its selected protocol. Reuse the same tools in additional gateways for other tool protocols; an A2A gateway serves an agent:

| Protocol | For |
|----------|-----|
| **MCP** | Claude Code, Cursor, Windsurf, and other MCP clients |
| **A2A** | Google's Agent-to-Agent orchestration |
| **UTCP** | Universal Tool Call Protocol |
| **Agent Skills** | 30+ AI coding agents via SKILL.md |

## 3. Call it from your AI (the payoff)

Point your assistant at the gateway and your API is live inside it. Grab the endpoint from the gateway's **Integrations** tab (it looks like `https://api.almyty.com/your-org/petstore`) and a key from its **Authentication** panel. Then, in Claude Code:

```bash
claude mcp add petstore --transport http \
  --header "x-api-key: gw_live_..." \
  https://api.almyty.com/your-org/petstore
```

![Your API's tools inside Claude Code](/screenshots/quickstart-claude-config.png)

Ask Claude to do something and it calls your API directly:

![Claude calling the gateway](/screenshots/quickstart-gateway-mcp.png)

If your client only speaks stdio, run the gateway as a local proxy instead:

```bash
npx @almyty/mcp-server your-org/petstore
```

That's the whole loop: **API → tools → gateway → your AI calling it.**

## Build an agent (optional)

Instead of handing tools to someone else's AI, build your own agent on top of them. Compose LLM calls, tool calls, conditions, and loops on a visual canvas, or run an autonomous agent that figures out the steps itself, with cross-vendor verification, memory, and human approvals built in.

![An agent built on your tools](/screenshots/agent-detail-overview.png)

Agents serve over the same protocols and an OpenAI-compatible endpoint, so anything that talks to OpenAI talks to your agent.
