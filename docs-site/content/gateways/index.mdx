# Gateways

Publish your tools once, reach them from any agent or client. A gateway takes the
tools you have already built and serves them over one protocol (MCP, UTCP or Agent
Skills) from an authenticated address. You pick the protocol and which tools a gateway
serves, so every address has a focused, purpose-built surface.

![A gateway detail page with its assigned tools, endpoint, and auth](/screenshots/gateway-detail-tools.png)

## The payoff

Scope a gateway to the tools you want, generate a key in its Authentication section, then
add it to Claude Code in one line:

```bash
claude mcp add petstore --transport http https://api.almyty.com/acme/petstore
# clients send: x-api-key: <your gateway key>
```

```text
> look up pet #2 and show its status
  Claude calls getPetById via almyty -> "Rosie", available
```

Create another gateway over the same tools to reach clients that speak another protocol.
Putting an agent in front of
people or other systems is a different job: web chats, website widgets, messaging
channels and A2A endpoints for other agents are channels of an agent, added on the agent's
**Channels** tab.

## Create a gateway

1. Open **Gateways** in the sidebar and click **Create gateway** to open `/gateways/new`
2. Under **Protocol**, pick **MCP**, **UTCP** or **Skills**. Nothing is picked for you
3. Under **Tools**, pick a whole API or single tools (a draft can't be served until it is active)
4. Name it; the address follows from the name, and **Advanced** changes the path and who can use it
5. Click **Create gateway**. An MCP or UTCP gateway shows its access key once, on the next page, with the setup for each client that speaks its protocol already filled in with the key. A Skills gateway has no access key: the Skills CLI signs in as you
6. Change which tools it serves from **Tool scoping** on the gateway page, and its auth from the **Authentication** section

An API's page has **Create gateway** too, with that API's tools already picked.

The gateway's **Integrations** tab gives you the live endpoint plus discovery URLs to
paste into any client:

![A gateway's MCP endpoint, SSE, and discovery URLs](/screenshots/gateway-petstore-integration.png)

## Protocols

Each gateway speaks the protocol it was created for, at `api.almyty.com/{org}/{gateway}`.
A gateway made before the protocol pick serves all three at one address: a JSON-RPC POST
is MCP, `/manual` and `/execute` are UTCP, and `/skills` lists the Agent Skills.

| Protocol | Reach it with | Endpoint |
|----------|---------------|----------|
| [MCP](/gateways/mcp) | Claude, Cursor, Windsurf, VS Code Copilot | `api.almyty.com/{org}/{gateway}` |
| [UTCP](/gateways/utcp) | Any HTTP client or agent framework | `api.almyty.com/{org}/{gateway}` |
| [Agent Skills](/gateways/skills) | 30+ coding agents, via the Skills CLI | Installed as `SKILL.md` files |

An agent, rather than a set of tools, reaches other agents over [A2A](/gateways/a2a): add
**Other agents (A2A)** as a channel on the agent, and it answers at
`api.almyty.com/{org}/channels/{channel-id}` with its Agent Card next to it.

Agents you build on almyty also get an [OpenAI-compatible endpoint](/api-reference/openai-compatible),
so anything that talks to the OpenAI API can call an agent without code changes.

## Control what each gateway exposes

- **[Authentication](/gateways/authentication)**: default-deny on every gateway. Add API
  key, bearer, basic, JWT, OAuth 2.1, and manage keys per client.
- **[Tool scoping](/gateways/tool-scoping)**: choose exactly which tools a gateway serves,
  with per-gateway rate limits and security policies on each tool.
