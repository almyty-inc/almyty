# UTCP Gateway

Call your tools over a plain REST API. A UTCP (Universal Tool Call Protocol) gateway lists and invokes tools with ordinary HTTP, so it works from any client library or agent framework with no special SDK.

![Gateway detail page](/screenshots/gateway-detail.png)

## Create the gateway

1. Open **Gateways** in the sidebar and click **Create Gateway**
2. Select **UTCP** as the protocol

![Create Gateway dialog](/screenshots/gateways-create-dialog.png)

3. Enter a name, slug, and optional description
4. Click **Create**

Assign tools from the **Tools** tab on the gateway detail page, then configure authentication from the **Authentication** tab.

![Assigning tools on the gateway Tools tab](/screenshots/gateway-detail-tools.png)

Your UTCP endpoint follows this pattern:

```
https://api.almyty.com/{org}/{gateway-slug}
```

There is no `/utcp` path segment. Every gateway is served from the same
`{org}/{gateway-slug}` URL, and the protocol is decided by the gateway's type, which you
set at creation time — not by a query parameter or an `Accept` header. A gateway created
as UTCP answers UTCP there; an MCP gateway answers MCP at the same URL shape.

## Endpoints

UTCP is a manual-driven protocol: you fetch one manual that describes every tool and how
to call it. There is no per-tool REST surface, and no `/health` on the gateway path
(platform health lives at `/health` on the API root).

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/.well-known/utcp` | public | Discovery: where the manual and execute URLs are, and what auth the gateway wants |
| `GET` | `/manual` | required | The UTCP manual — every tool on this gateway, with its call template |
| `POST` | `/execute` | required | Run a tool through almyty (proxy mode, an almyty extension) |

Any other sub-path returns `404 Unknown UTCP action`.

### Discovery

```bash
curl https://api.almyty.com/acme/tools-api/.well-known/utcp
```

```json
{
  "utcp_version": "1.0.0",
  "manual_version": "<gateway-uuid>:2026-01-01T12:00:00.000Z",
  "manual_url": "https://api.almyty.com/acme/tools-api/manual",
  "execute_url": "https://api.almyty.com/acme/tools-api/execute",
  "server": {
    "name": "almyty",
    "version": "1.0.0",
    "description": "almyty UTCP gateway"
  }
}
```

If the gateway has auth configured, an `auth` field describes it (one object, or an array
when several methods are active).

### Manual

The manual is snake_case throughout — UTCP SDKs parse against these exact field names.
Each tool carries an inline `tool_call_template` pointing at the upstream API, so a UTCP
client can call the tool directly without proxying through almyty.

```bash
curl https://api.almyty.com/acme/tools-api/manual \
  -H "x-api-key: your-gateway-key"
```

```json
{
  "utcp_version": "1.0.0",
  "manual_version": "<gateway-uuid>:2026-01-01T12:00:00.000Z",
  "tools": [
    {
      "name": "get_users",
      "description": "Retrieve a list of users with pagination",
      "inputs": {
        "type": "object",
        "properties": {
          "page": { "type": "integer" },
          "limit": { "type": "integer" }
        }
      },
      "outputs": { "type": "object" },
      "tags": ["openapi", "auto-generated"],
      "tool_call_template": {
        "call_template_type": "http",
        "url": "https://api.example.com/users",
        "http_method": "GET",
        "content_type": "application/json",
        "headers": {}
      }
    }
  ]
}
```

Secrets are never inlined: an API key, password, or client secret in the call template's
`auth` block is replaced with a `{{...}}` placeholder, because the manual is served to
anyone with gateway access.

Only tools backed by an API operation appear in the manual. A hand-written JavaScript or
LLM tool has no HTTP target to describe, so it has no call template and is omitted — reach
those through `/execute`, or through an MCP or Skills gateway.

The manual is cached for five minutes per gateway.

### Execute

`/execute` is an almyty extension, not part of the UTCP spec. It runs the tool
server-side, which means almyty supplies the API's stored credentials and enforces the
gateway's rate limits and per-tool security policy. `toolId` is the tool's almyty id — the
UUID in the tool's dashboard URL (`/tools/{id}`).

```bash
curl -X POST https://api.almyty.com/acme/tools-api/execute \
  -H "x-api-key: your-gateway-key" \
  -H "Content-Type: application/json" \
  -d '{
    "toolId": "d3b0...-tool-uuid",
    "parameters": { "page": 1, "limit": 10 }
  }'
```

An optional `options` object takes `timeout`, `retries`, and `skipCache`. The response
always carries `success` and `metadata`:

```json
{
  "success": true,
  "data": {
    "users": [
      { "id": "1", "name": "Alice", "email": "alice@example.com" }
    ],
    "total": 42
  },
  "metadata": {
    "executionTime": 234,
    "toolId": "d3b0...-tool-uuid",
    "requestId": "utcp-...",
    "timestamp": "2026-01-01T12:00:00.000Z",
    "cached": false,
    "retryCount": 0
  }
}
```

A failure returns `"success": false` with an `error` object instead of `data`.

## Connect from code

### Python

```python
import requests

base = "https://api.almyty.com/acme/tools-api"
headers = {"x-api-key": "your-gateway-key"}

manual = requests.get(f"{base}/manual", headers=headers).json()
tools = manual["tools"]

result = requests.post(
    f"{base}/execute",
    headers=headers,
    json={"toolId": "d3b0...-tool-uuid", "parameters": {"page": 1, "limit": 10}},
).json()["data"]
```

### JavaScript

```javascript
const base = "https://api.almyty.com/acme/tools-api";
const headers = { "x-api-key": "your-gateway-key" };

const { tools } = await fetch(`${base}/manual`, { headers }).then(r => r.json());

const { data } = await fetch(`${base}/execute`, {
  method: "POST",
  headers: { ...headers, "Content-Type": "application/json" },
  body: JSON.stringify({ toolId: "d3b0...-tool-uuid", parameters: { page: 1, limit: 10 } }),
}).then(r => r.json());
```

## Error codes

`/execute` answers with HTTP 200 and `"success": false` — the code is in `error.code`:

| Code | Description |
|------|-------------|
| `EXECUTION_ERROR` | The tool ran and failed (upstream error, validation, timeout) |
| `INTERNAL_ERROR` | The call could not be dispatched at all |

Everything before the tool runs is an ordinary HTTP error:

| HTTP Status | Description |
|-------------|-------------|
| 401 | Missing or invalid authentication |
| 404 | Unknown UTCP action (a sub-path other than `manual`, `execute`, or `.well-known/utcp`) |
| 429 | Gateway rate limit exceeded — the body carries `code`, and `retryAfter` when known |

See [Gateway Authentication](/gateways/authentication) for the auth methods you can put in front of the endpoint.
