# Publishing a channel

Adding a channel records where an agent will be; **publishing** it is the separate decision to let people reach it. This page covers what each kind of channel asks for before and after it is published. Channels are added on the agent's **Channels** tab with **Add channel**; see [Channels](/channels).

## Slack: Add to Slack

The Slack channel leads with **Add to Slack**. Create a Slack app at api.slack.com/apps, then pick its credentials, or select **Create one here** and enter its client ID, client secret and signing secret, and publish. The page then shows the redirect URL to add to your Slack app and the install link to share; every workspace that installs it is listed with a revoke action. A single workspace can use a bot token credential instead, under **Advanced**.

![The Slack channel with its keys](/screenshots/channel-slack-keys.png)

## The other messaging channels

Telegram, WhatsApp and the rest take their platform keys as a credential, picked on the channel's own page or created there with **Create one here**, so you stay on the agent instead of being sent elsewhere to wire up a gateway. The credential lands on Credentials like any other. Pick it and publish. See [Chat Interfaces](/interfaces) for what each platform needs and where to paste almyty's callback URL.

Once published, the channel is live and shows an **Unpublish** action.

![The Slack channel published and live](/screenshots/channel-slack-live.png)

Publishing again re-syncs the channel rather than failing, because the second attempt is usually you reapplying a settings change. **Unpublishing** stops the channel answering without deleting it, so taking an agent off Slack for an afternoon does not mean re-registering a Slack app afterwards; publishing again keeps the same address and keys.

## Web chat

The **Web chat** is a hosted chat on its own address, carrying the agent's name, greeting, colour and AI disclosure rather than the dashboard chrome. Its address is made from the agent's name; change it under **Address** on its page. It is a web address, so it has to be free across almyty, and the page says so when another web chat has it. Publishing shows the link straight away; your own domain and the sites allowed to embed it are on the same page. Visitors can attach images, PDFs and text files next to the message box, up to five per message.

![The published web chat channel](/screenshots/channel-web-published.png)

![The branded hosted chat](/screenshots/hosted-chat.png)

See **[Hosted Chat App](/hosted-chat)** for addressing, custom domains and self-hosting.

## Website widget

The **Website widget** puts the agent in a chat bubble on a site you already have. Publish it, and its page gives you one line to paste before the closing `body` tag:

```html
<script src="https://<api-host>/gateways/<gateway-id>/widget.js" async></script>
```

The widget takes its colour, name, greeting, theme and AI disclosure from the agent's branding (or the channel's own), so it looks the same as the web chat. On its page you choose where it sits (bottom right or left) and its launcher icon, with a live preview of the real widget, and list the sites allowed to show it. The widget has no sign-in: anyone on an allowed site can use it, within the spend and message limits (each conversation is a visitor), so it only goes on a channel anyone can use. Visitors can attach images, PDFs and text files with the **+** next to the input. When visitors are allowed to, the widget offers *Download my chat* and *Delete my chat*.

## Other agents (A2A)

**Other agents (A2A)** lets agents elsewhere call this agent over Google's Agent-to-Agent protocol. Publish it, and its page shows the Agent Card URL and the JSON-RPC endpoint, `https://<api-host>/<org>/channels/<channel-id>`. Under **How other agents sign in**, make a key for each caller; each call sends it in the `x-api-key` header. Each key has its own share of the per-visitor message limit, and each task runs under the per-run and spend limits. The card and the endpoint answer only while the channel is published and the agent is active. See **[A2A](/gateways/a2a)** for the methods and the card.

## Post scheduled results

A published messaging channel can also start a conversation: an agent's
[schedule](/agents/scheduling) can send each result to it, such as a sales summary
into a Slack channel every weekday at 8:00, a report to a Teams chat, or an email
to the team. On the schedule page, under **Send the result to**, choose the channel
and where on it: a Slack channel the bot is in, a Teams channel or chat where the bot
has been talked to, email addresses, or a phone number. The web chat, the widget and
the apps answer people who are there, so they are not offered.

The post goes out like a reply: through the same bot, with the channel's AI
disclosure line at the top, and within the channel's spend limit. A post the platform
refuses shows on the run and in your notifications.
## AI disclosure

Every channel people talk to (the web chat, the website widget and each messaging channel) has an **AI disclosure** switch, on by default. The web chat and the widget show the disclosure line under the message box; a messaging channel puts it before the first reply of each conversation, and at the top of each scheduled post. The line is the one in **Branding and visitor rules** (or the channel's own), and *You are chatting with an AI assistant.* when none is set. Turning the switch off removes the disclosure, which needs the white-label entitlement. See [Compliance](/compliance).

## What gates a channel open to anyone

While you are still editing, the channel's page lists what stops it being published, rather than letting you discover it when a publish is refused. The ones that matter for anything open to the public:

- **A spend limit.** Anyone with the link or the download can spend against your model keys, so a channel open to anyone needs a per-run limit.
- **Message limits.** One visitor must not be able to use up the agent for everyone else. Per-visitor and per-IP limits are separate, because a web chat visitor has no account.
- **No local access on a public download.** A desktop or terminal app that touches the machine it lands on cannot also be open to anyone.

Who may use a channel is never read as unset: when nothing is chosen, it is open to anyone, because the permissive reading of missing configuration is the one that gets someone billed. A per-run or message limit left empty is stored as unset, not as zero.
